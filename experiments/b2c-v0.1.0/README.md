# b2c-v0.1.0 — 개인 메일·일정 브리핑 비교

**실험 버전 `b2c-v0.1.0` · 보고서 revision `v1` · 실제 모델 호출 · 단일 사례·미보정 파일럿**

동일한 개인 자료에서 중요 업무를 골라 제안하는 능력을 비교했다. 이번 사례에서는 Terra가 가장 안정적이었고, Luna는 신중하지만 일부 누락·우선순위 보완이 필요했다. Solar는 중요한 사실·기한 오류 때문에 답변을 그대로 사용하기 어려웠다. 세 모델 모두 정상 응답했지만, 정상 종료와 업무 품질 통과는 다른 결과다.

출처는 [초기 과제 조사](../../research/scenario-candidates.md)를 연결한다. 개인형 에이전트의 종합 활용 가능성을 이 한 과제로 확정하지 않는다. 역사적 Q1~Q4 결과와 점수를 합산하지 않는다.

## 실행 조건

- GPT: `gpt-6-luna`, `gpt-6.1-terra` / `openai-codex` / `medium`. 송신 요청의 reasoning 필드를 확인했다.
- Solar: `solar-mini-4-5-preview` / `solar-beta` / Upstage Chat Completions. 제공사 기본 추론 설정이며 GPT medium과 동일하다고 가정하지 않는다.
- 동일 고정 입력 전체 전달, 도구 0개, 기억·프로젝트 문서 주입·백그라운드 검토 비활성화.
- 모델별 한 turn, 순차 실행, 600초 프로세스 종료 한도. 실제 완료 배치의 요청은 각 1회였다.
- Solar 출력 상한은 8,192토큰. Codex 경로는 같은 상한 필드를 제거하므로 공통 출력 한도를 강제한 비교가 아니다.
- Hermes AIAgent는 기존 의존성을 읽는 비공개 worker로 실행했다. 설치 updater bootstrap은 건너뛰었으며 stock CLI와 다른 조건이다.
- 실행 기준 코드 커밋은 `135feb08c8c6a4d81ebf66a7cfe9cb98ef002ea7`, 당시 working tree는 dirty였다. 당시 worker 소스는 비공개 원자료 목록에 보존했다. 후속 문서 커밋을 실행 코드 버전으로 소급하지 않는다.
- 사용자 승인 범위는 고정 자료 읽기·제안이다. Solar 베타 데이터 보관 조건은 실행 전에 고지하고 사용자 인지를 확인했다. gateway·기본 모델·개인 서비스 설정은 변경하지 않았다.

처음 제한 네트워크에서 GPT 두 run이 ConnectError로 중단됐다. 원본과 개입 기록을 별도로 보존했고, 위 표는 네트워크 권한 확장 후 새로 실행한 완료 배치만 포함한다. 환경 실패를 모델 오답으로 집계하지 않았다.

## 비용 — 실제 청구액이 아닌 단가 환산

2026-11-17 확인한 OpenAI Standard API 장문 요율을 적용했다. 입력이 272k를 넘으므로 전체 요청에 입력·캐시 2배, 출력 1.5배 요율을 적용한다. GPT는 실제로 구독 인증 경로였으며 이 계산은 실제 구독 청구액이 아니다. Solar는 사용자가 지정한 대체 단가로 계산했으며 실제 preview 가격·원가로 주장하지 않는다.

| US$/백만 토큰 | 입력 | 캐시 입력 | 출력 |
|---|---:|---:|---:|
| Luna — 장문 | 0.20 | 0.02 | 0.75 |
| Terra — 장문 | 2.00 | 0.10 | 7.50 |
| Solar — 사용자 지정 | 0.0291 | 미지정 | 0.3815 |

`환산 비용 = [(전체 입력 − 캐시 입력) × 입력 단가 + 캐시 입력 × 캐시 단가 + 출력 × 출력 단가] / 1,000,000`

이번 캐시 읽기·쓰기는 모두 0이라 캐시 비용·할인을 적용하지 않았다. 캐시 쓰기가 있는 향후 실행에는 해당 retention 단가와 중복 집계 방지 규칙을 별도로 기록해야 한다.

| 모델 | 입력 비용 | 출력 비용 | 총 환산 비용 | 전체 시간 |
|---|---:|---:|---:|---:|
| Luna | $0.0589646 | $0.0006420 | **$0.0596066** | 20.2초 |
| Terra | $0.5896440 | $0.0103875 | **$0.6000315** | 30.9초 |
| Solar | $0.0086318 | $0.0005589 | **$0.0091907** | 248.8초 |
| 합계 | — | — | **$0.6688288** | 약 5분 |

시간은 실측이고 비용은 가격표를 적용한 가정값이다. 초기 연결 실패·개발·조사·judge 비용은 포함하지 않았다. 성공당 비용은 아직 산출하지 않는다. 높은 품질로 검증된 업무 성공 여부와 반복 분모가 확보되지 않았기 때문이다.

가격 출처: [공식 가격표](https://developers.openai.com/api/docs/pricing.md), [Luna 장문 조건](https://developers.openai.com/api/docs/models/gpt-6-luna.md), [Terra 장문 조건](https://developers.openai.com/api/docs/models/gpt-6.1-terra.md). 계산 가정과 소수점 원본: [cost-v1.json](results/cost-v1.json).

## 정성 결과 — 수동 판정 v1

평가자는 현재 Codex `gpt-6.1-sol`(자기 보고)이다. 별도 외부 judge API를 호출하지 않았다. 평가자가 하네스를 준비했고 모델 이름을 이미 알고 있었으므로 블라인드·독립 평가가 아니다. 사용자 중요도 기준표는 미작성이고 후보 항목은 사후 검토로 정리했다.

| rubric | Luna | Terra | Solar |
|---|---:|---:|---:|
| coverage: 중요한 항목의 포괄성 | 0.5 | 1 | 0.5 |
| prioritization: 우선순위·선별 | 0.5 | 1 | 0 |
| grounding: 근거·불확실성 | 1 | 1 | 0 |

척도는 1=검토 범위에서 대체로 충족, 0.5=의미 있는 보완 필요, 0=중대한 문제, null=판단 불가다. 객관적 정답률·성공 확률·100점 환산이 아니다. Terra의 1점은 완벽함을 뜻하지 않는다.

| 쟁점 | Luna | Terra | Solar |
|---|---|---|---|
| 발송 실패 후보 | 누락; 원래 메일의 중요도는 불명 | 미확인 전달 상태를 확인하도록 제안 | 별도 업무 메일과 근거 없이 연결 |
| 문자 깨진 안내 | 해석 한계를 명시 | 예정과 실제 처리 상태를 구분 | 날짜를 다른 종류의 마감으로 확정 |
| 입금 대기 주문 | 현재 상태부터 확인 | 상대 시한의 기산점·처리 상태를 구분 | 기한이 지났을 수 있는데 오늘 입금을 요구 |
| 일정·정보 선별 | 간결하지만 누락·우선순위 보완 | 가장 균형적; 선택 항목은 다소 많음 | 과도한 일정 나열과 당일 일정 자기모순 |

Solar에서 관찰한 중대한 문제는 지급일→회신 마감 변환, 서로 다른 메일의 연결·날짜 오류, 미확인 주문의 즉시 입금 제안, 당일 일정 자기모순이다. 이를 일반 모델의 오류율로 환산하지 않는다. 원자료 없이 확인 가능한 것은 이 보고의 판정 구조이며, 세부 주장의 독립 검토에는 비공개 근거가 필요하다.

기계 판정 요약: [quality-v1.json](results/quality-v1.json). 각 finding은 run 내부의 `hermes-message-1`(입력), `hermes-message-2`(답변)와 입력 내부 source ID를 참조한다. 이벤트 ID가 있다는 사실만으로 주장의 진실성이 증명되지는 않는다.

## Verifier와 완전성

모든 run에서 고정 입력 전체가 HTTP 요청과 user 메시지에 그대로 포함됨, 원본 DB 메시지 ID와 import ID 일치, assistant 답변 일치, 도구 없음, 조상·자식 세션 없음이 확인됐다.

라이브 메일·캘린더 상태는 독립 감사하지 않아 기존 상태 verifier는 세 모델 모두 **unknown**이다. GPT의 전체 judge verdict도 unknown을 유지했다. Solar는 답변의 명확한 결함을 근거로 fail을 기록했다. unknown은 해당 증거가 없다는 의미이며 자동 fail이나 pass가 아니다.

DB의 ended_at은 비어 있으나 completed=true 결과와 프로세스 종료가 관찰됐다. 원본 DB를 수정하지 않았다. 서버가 실제로 제공한 모델 정체는 별도 attestation으로 확인하지 못했다.

## 다음 실험과 변경 이력

이 실험이 확인한 것은 고정 자료 판단 능력이다. 다음 버전에서는 사용자 기준을 사전에 기록하고, 필요한 원문·종일 일정 타입을 보존하며, 의미 수준 verifier와 반복 실행을 추가한다. 도구형 과제와 무개입 사례는 별도 task·실험 버전으로 추가한다. 이번 입력·답변·점수를 소급 수정하지 않는다.

- v1: 이미 사용자에게 보고한 측정·판정·비용을 GitHub용 요약으로 정리. 원문은 비공개로 유지.
